# Decisions by regard: what every rung of the scale actually decides

GENERATED by the Maps fixtures in `CalradiaRemembers.Tests/Maps`. Do not edit. A test fails when this file
no longer matches the code; see `docs/maps/README.md`.

Every cell is a REAL CALL into a real policy, swept from -100 to +100. Only rules that read a regard value
and nothing else can appear: a decision that also weighs traits, distance or a die roll is not a function of
the scale alone, and would need its own table.

**Two scales, not one.** `NpcProfile.ReputationWithPlayer` is the mod's own regard, built in conversation;
`Hero.GetRelation` is vanilla's. Both are ints from -100 to 100 and the code calls both "regard" in places, so
each column below says which one its rule was written for. `?` means the rule's own doc never says, which is
the thing worth fixing.

12 rules. A CHANGED CELL in this file is a changed behaviour: that is what makes this the safety
net for giving regard a type and its tiers one home (see `ROADMAP.md`).

## What this table does not show yet, and why

12 rules can be swept here. Against that, the code declares **91 regard-named thresholds**
(constants whose name carries regard, relation or reputation). The difference is the gap: those thresholds are
compared INLINE, at the place that wants the answer, so there is no function to call and nothing to sweep.

That gap is the thing to close, and closing it is what makes the rest of the scale measurable: a decision asked
of the value (`regard.IsFriend`) can be swept; a decision taken about the value (`regard >= FriendThreshold`)
cannot. Each one moved into a rule adds a column here.
